Must-know one-liners

  • JVM runs bytecode · JRE = JVM + libraries · JDK = JRE + tools. Bytecode is platform independent, the JVM is not.
  • Java is always pass-by-value. For objects, the reference is copied.
  • Widening is automatic, narrowing needs a (cast).
  • Four pillars: Encapsulation, Abstraction, Inheritance, Polymorphism.
  • Dependency (uses, - - ->) < Association (knows, ──) < Aggregation (◇, part survives) < Composition (◆, part dies).
  • Constructor: same name, no return type, not inherited. The default one is added only if none is written. this()/super() must come first.
  • Constructors run top-down (Object → … → child). Methods resolve bottom-up (child → … → Object).
  • Overloading = same name, different params, compile time. Overriding = same signature, subclass, runtime.
  • static, private and final methods and fields are not dynamically dispatched.
  • abstract can't combine with private, final or static.
  • Interface: fields are public static final. Default, static (Java 8) and private (Java 9) methods are allowed. A class can implement many.
  • Immutable: final class, private final fields, no setters, defensive copies in and out.
  • == compares references, equals() compares content. Override hashCode together with equals.
  • Comparable: compareTo(o), one natural order, inside the class, java.lang. Comparator: compare(a,b), many orders, outside the class, java.util.
  • clone(): needs Cloneable, shallow by default, doesn't call a constructor.
  • Checked = compiler forces handling (IOException). Unchecked = RuntimeException (NPE, AIOOBE).
  • finally always runs except on System.exit or a JVM crash. Catch specific types before general ones.
  • assert is off by default. Enable with java -ea. Don't use it for public argument checks.
  • Serialization: Serializable, writeObject/readObject. transient and static fields are skipped. Keep a serialVersionUID.
  • Byte streams: InputStream/OutputStream (binary). Character streams: Reader/Writer (text, Unicode).
  • JUnit 5 = Platform + Jupiter + Vintage. Key annotations: @Test, @BeforeEach, @AfterEach, @BeforeAll, @AfterAll, @Disabled.
  • UML structural (class, object, component, deployment, package) vs behavioural (use case, sequence, activity, state).
  • JavaFX: Stage → Scene → Nodes. Event phases: target selection → route construction → capturing (filters) → bubbling (handlers).
  • Thread states: NEW, RUNNABLE, BLOCKED, WAITING, TIMED_WAITING, TERMINATED.
  • start() creates a new thread. run() is a normal method call.
  • Prefer Runnable over extending Thread, and prefer ExecutorService over both.
  • Pool steps: create → submit → get results → shutdown. Risks: deadlock, leakage, thrashing, unbounded queue.
  • Granularity: fine = more overhead but better balance. Coarse = less overhead but load imbalance. Aim for a few tasks per core.
  • Race condition = shared mutable data + concurrent access + at least one write. count++ isn't atomic.
  • Every object has a monitor. synchronized acquires it. It is reentrant and released automatically.
  • wait() releases the lock (Object method, call it inside a while). sleep() keeps the lock.
  • Deadlock (Coffman): mutual exclusion, hold and wait, no preemption, circular wait. Fix with lock ordering.
  • volatile gives visibility and ordering, but not atomicity. Happens-before: unlock → lock, volatile write → read, start, join.
  • Creational: Singleton, Factory, Prototype · Structural: Adapter, Decorator, Facade, Composite, Proxy, Flyweight · Behavioural: Iterator, Strategy, Template, Observer, State, Chain of Responsibility.

Answer-writing template for 5-mark questions

  1. Definition (1–2 lines, use the keywords).
  2. Diagram or table, especially for "differentiate" questions (5–6 rows).
  3. Code: a short, complete program with comments.
  4. Output and a 2-line explanation of the output.
  5. Advantages / applications (3–4 bullets).
